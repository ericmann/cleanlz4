# Design notes

## Decisions

- Lint attributes use the `cfg_attr(not(test), deny(...))` form in `crates/cleanlz4/src/lib.rs`, so the no-panic lints bind library code while tests may use `unwrap`, `expect` and indexing (SPEC section 3.3). Implements: project rule on no reachable panic; held by the `no-panic-lint-suppression` constraint and by `make check` (clippy).
- Tool versions are recorded in `testdata/MANIFEST.json` `tools`: the oracle library version is read from `Cargo.lock` (the SPEC section 6.5 surface has no version function), and the installed `lz4` program's first `-V` line is recorded separately; the two may differ in version (CLI 1.9.4, library 1.10.0 at the time of recording). Implements: SPEC section 5.2 (corpus provenance); held by `crates/oracle/tests/manifest.rs` `manifest_records_tool_versions`.
- The manifest is written by the `manifest` binary, never by hand; cleanlz4's own measurement (a SHA-256 over each downloaded archive and each extracted file) is the provenance. Held by `corpus_files_on_disk_match_manifest`.
- The oracle's block functions are wrapped in `crates/oracle/src/ffi.rs` as safe slice-taking functions, the only place with `unsafe`; `crates/oracle/src/block.rs` adds length checks (lengths beyond a C `int` panic, as this is test tooling) and a unit `Rejected` error. Implements: SPEC section 6.5 (Block); cleanlz4's own tooling decision. Held by `crates/oracle/tests/ffi_block.rs`.
- The oracle's frame functions are wrapped by RAII contexts in `crates/oracle/src/ffi.rs`; `crates/oracle/src/frame.rs` offers `compress_frame`, `decompress_frames` and `content_checksum_of`. The context version argument is the constant the binding exports. XXH32 vectors come only from the last four bytes of a frame written with the content checksum on. Implements: Frame format, Content Checksum; SPEC section 6.5 (Frame compression, Frame decompression). Held by `crates/oracle/tests/ffi_frame.rs`.
- `Error::BlockSizeExceeded` exists as a seventeenth variant because the frame format forbids a data block larger than the frame's maximum block size and SPEC section 6.2's list has no variant for it. Implements: Frame format, Data Blocks ("Block_Size shall never be larger than Block_Maximum_Size"). Held by `error.rs` unit tests; later by the frame tests.
- XXH32 Step 1 (xxHash spec, "Step 1. Initialize internal accumulators"): four accumulators from the seed, and the single-accumulator `seed + PRIME32_5` start when the total length is under 16. Held by `xxh32.rs` unit tests and `crates/oracle/tests/xxh32.rs` `matches_oracle_content_checksum_for_lengths_0_to_300`.
- XXH32 Step 2 (xxHash spec, "Step 2. Process stripes"): lanes read little-endian from 16-byte stripes with wrapping arithmetic; the streaming form buffers a partial stripe. Held by `streaming_equals_one_shot_for_every_split`.
- XXH32 Step 3 (xxHash spec, "Step 3. Accumulator convergence"): rotations 1, 7, 12, 18, applied only when at least one stripe was consumed (total length of 16 or more). Held by `matches_oracle_for_large_random_inputs`.
- XXH32 Step 4 (xxHash spec, "Step 4. Add input length"): the total length is kept as 64 bits and its low 32 bits are added. Held by `lengths_around_stripe_boundaries_differ`.
- XXH32 Step 5 (xxHash spec, "Step 5. Consume remaining input"): four-byte words, then single bytes. Held by the oracle length sweep 0 to 300.
- XXH32 Steps 6 and 7 (xxHash spec, "Step 6. Final mix (avalanche)" and "Step 7. Output"): the digest is the numeric value; the canonical big-endian form is not needed because the frame format stores checksums little-endian (Frame format, Header Checksum, Block checksum). Held by `header_checksum_byte_matches_oracle_frames` and `block_checksum_matches_oracle_frames`.
- XXH32 test vectors come only from the oracle: the last four bytes of a frame written with the content checksum on are XXH32 of the content with seed 0 (Frame format, Content Checksum). Seeds other than 0 cannot be checked against the oracle; they are covered only by `seed_changes_the_digest` and by streaming-equals-one-shot. Held by `crates/oracle/tests/xxh32.rs`.
- Block sequences (Block format, "Compressed block format"): a token's high nibble is the literal length and its low nibble the match length less 4; a nibble of 15 is extended by bytes until one is below 255; the offset is two bytes little-endian. Held by `block.rs` tests `literal_length_examples_48_280_and_15` and `match_length_extension_bytes`.
- Overlapping matches (Block format, "Compressed block format": "bytes just copied are copied again"): matches copy in passes of at most `offset` bytes from a fixed start, which yields the same bytes as a byte-at-a-time copy. Held by `overlapping_match_with_offset_1_repeats_the_last_byte`.
- Offsets resolve against the whole output buffer, including bytes present before the call (Block format, "Implementation notes", Safe decoding; the frame layer uses it for linked blocks). Offset 0 is `ZeroOffset`; reaching before the buffer is `OffsetOutOfRange`. Held by `zero_offset_is_rejected`, `offset_before_output_start_is_rejected`, `match_reads_bytes_present_before_the_call`.
- Safe decoding (Block format, "Implementation notes", Large lengths and Safe decoding): lengths are summed with `checked_add`; an overflow, or output that would pass the limit, is `OutputLimitExceeded`, checked before any byte is copied. Running out of input inside a length, literals or offset is `TruncatedInput`, and so is an empty block. Held by `output_limit_is_enforced_before_copying`, `truncation_in_length_literals_and_offset_is_rejected`.
- End of block rule 1 (Block format, "End of block conditions", 1): a block that ends right after a match is `EndOfBlockViolation`. Held by `rule_1_block_ending_after_a_match`.
- End of block rule 2 (Block format, "End of block conditions", 2): a block with a match whose final literal run is under 5 bytes is `EndOfBlockViolation`; a literals-only block may be any length, including the single zero token for empty input. Held by `rule_2_fewer_than_five_final_literals`, `single_zero_token_is_the_empty_block`.
- End of block rule 3 (Block format, "End of block conditions", 3): the check (fewer than 12 bytes of the block's output from the last match's start to the end) exists but is switched off by default; see the P1-07 entry below. Held by `rule_3_last_match_within_twelve_bytes_of_the_end`.
- The three rules sit behind one private policy constant so a rule is relaxed in a single place. The document permits rejection ("a conformant decoder is allowed to reject the block as incorrect"), not requires it.
- Policy decision (P1-07, from `docs/spikes/P1-06.md`, Policy): rule 1 enforced, rule 2 enforced, rule 3 not enforced (the oracle accepts rule 3 shapes given room in the output buffer; Block format, "End of block conditions": a decoder "is allowed to reject"), empty input rejected as `TruncatedInput`, the single byte 0x00 accepted as the empty block, and the final token's low four bits ignored. Held by `crates/oracle/tests/eob.rs` `end_of_block_probes_agree_with_the_oracle`, `every_prefix_of_small_oracle_blocks_agrees`, `single_byte_corruptions_of_small_oracle_blocks_agree`.
- The low four bits of the final token are ignored: the document sets no requirement on them (Block format, "End of block conditions", 1).
- The oracle's end-of-block behaviour was observed as a black box in `docs/spikes/P1-06.md` (cleanlz4's own measurement through `crates/oracle`): it rejects rule 1 and rule 2 violations and the empty input, accepts the single zero byte and any final-token low nibble, and rejects rule 3 shapes only at exact output capacity. Differential tests therefore decode the oracle side with slack capacity. Held by `crates/oracle/tests/craft.rs` (the builder) and the spike's table.
- Dictionary-prefixed blocks (Block format, "Compressed block format", the offset; Frame format, "Dictionary ID", "a kind of known prefix"): the dictionary is treated as history that sits just before the output, so an offset past the start of the output continues into the dictionary's tail, and a match may start there and run into the output. An offset beyond output plus dictionary is `OffsetOutOfRange`. No trimming is needed because an offset is at most 65,535. Held by `block.rs` tests `match_reaches_into_the_dictionary_tail`, `match_starts_in_the_dictionary_and_continues_into_output`, `offset_past_the_dictionary_start_is_rejected`, `empty_dictionary_behaves_like_no_dictionary`, `only_the_reachable_tail_of_a_long_dictionary_matters`.

## Differential rules

- Zero offset (Block format, "Compressed block format": "0 is an invalid `offset` value ... denotes an invalid (corrupted) block"): the oracle accepted a corrupted block whose offset became 0 (found by `single_byte_corruptions_of_small_oracle_blocks_agree`), while cleanlz4 returns `ZeroOffset`. In block differentials, cleanlz4 `ZeroOffset` against an oracle accept is allowed; every other accept/reject pair must agree. Decoding on the oracle side uses the original length plus 65,536 bytes of capacity (P1-06).
