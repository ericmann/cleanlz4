# Design notes

## Decisions

- Lint attributes use the `cfg_attr(not(test), deny(...))` form in `crates/cleanlz4/src/lib.rs`, so the no-panic lints bind library code while tests may use `unwrap`, `expect` and indexing (SPEC section 3.3). Implements: project rule on no reachable panic; held by the `no-panic-lint-suppression` constraint and by `make check` (clippy).
- Tool versions are recorded in `testdata/MANIFEST.json` `tools`: the oracle library version is read from `Cargo.lock` (the SPEC section 6.5 surface has no version function), and the installed `lz4` program's first `-V` line is recorded separately; the two may differ in version (CLI 1.9.4, library 1.10.0 at the time of recording). Implements: SPEC section 5.2 (corpus provenance); held by `crates/oracle/tests/manifest.rs` `manifest_records_tool_versions`.
- The manifest is written by the `manifest` binary, never by hand; cleanlz4's own measurement (a SHA-256 over each downloaded archive and each extracted file) is the provenance. Held by `corpus_files_on_disk_match_manifest`.
- The oracle's block functions are wrapped in `crates/oracle/src/ffi.rs` as safe slice-taking functions, the only place with `unsafe`; `crates/oracle/src/block.rs` adds length checks (lengths beyond a C `int` panic, as this is test tooling) and a unit `Rejected` error. Implements: SPEC section 6.5 (Block); cleanlz4's own tooling decision. Held by `crates/oracle/tests/ffi_block.rs`.
- The oracle's frame functions are wrapped by RAII contexts in `crates/oracle/src/ffi.rs`; `crates/oracle/src/frame.rs` offers `compress_frame`, `decompress_frames` and `content_checksum_of`. The context version argument is the constant the binding exports. XXH32 vectors come only from the last four bytes of a frame written with the content checksum on. Implements: Frame format, Content Checksum; SPEC section 6.5 (Frame compression, Frame decompression). Held by `crates/oracle/tests/ffi_frame.rs`.
- `Error::BlockSizeExceeded` exists as a seventeenth variant because the frame format forbids a data block larger than the frame's maximum block size and SPEC section 6.2's list has no variant for it. Implements: Frame format, Data Blocks ("Block_Size shall never be larger than Block_Maximum_Size"). Held by `error.rs` unit tests; later by the frame tests.
- XXH32 Step 1 (xxHash spec, "Step 1. Initialize internal accumulators"): four accumulators from the seed, and the single-accumulator `seed + PRIME32_5` start when the total length is under 16. Held by `xxh32.rs` unit tests and `crates/oracle/tests/xxh32.rs` `matches_oracle_content_checksum_for_lengths_0_to_300`.
- XXH32 Step 2 (xxHash spec, "Step 2. Process stripes"): lanes read little-endian from 16-byte stripes with wrapping arithmetic; the streaming form buffers a partial stripe. Held by `streaming_equals_one_shot_for_every_split`.
- XXH32 Step 3 (xxHash spec, "Step 3. Accumulator convergence"): rotations 1, 7, 12, 18, applied only when at least one stripe was consumed (total length of 16 or more). Held by `matches_oracle_for_large_random_inputs`.
- XXH32 Step 4 (xxHash spec, "Step 4. Add input length"): the total length is kept as 64 bits and its low 32 bits are added. Held by `lengths_around_stripe_boundaries_differ`.
- XXH32 Step 5 (xxHash spec, "Step 5. Consume remaining input"): four-byte words, then single bytes. Held by the oracle length sweep 0 to 300.
- XXH32 Steps 6 and 7 (xxHash spec, "Step 6. Final mix (avalanche)" and "Step 7. Output"): the digest is the numeric value; the canonical big-endian form is not needed because the frame format stores checksums little-endian (Frame format, Header Checksum, Block checksum). Held by `header_checksum_byte_matches_oracle_frames` and `block_checksum_matches_oracle_frames`.
- XXH32 test vectors come only from the oracle: the last four bytes of a frame written with the content checksum on are XXH32 of the content with seed 0 (Frame format, Content Checksum). Seeds other than 0 cannot be checked against the oracle; they are covered only by `seed_changes_the_digest` and by streaming-equals-one-shot. Held by `crates/oracle/tests/xxh32.rs`.
- Block sequences (Block format, "Compressed block format"): a token's high nibble is the literal length and its low nibble the match length less 4; a nibble of 15 is extended by bytes until one is below 255; the offset is two bytes little-endian. Held by `block.rs` tests `literal_length_examples_48_280_and_15` and `match_length_extension_bytes`.
- Overlapping matches (Block format, "Compressed block format": "bytes just copied are copied again"): matches copy in passes of at most `offset` bytes from a fixed start, which yields the same bytes as a byte-at-a-time copy. Held by `overlapping_match_with_offset_1_repeats_the_last_byte`.
- Offsets resolve against the whole output buffer, including bytes present before the call (Block format, "Implementation notes", Safe decoding; the frame layer uses it for linked blocks). Offset 0 is `ZeroOffset`; reaching before the buffer is `OffsetOutOfRange`. Held by `zero_offset_is_rejected`, `offset_before_output_start_is_rejected`, `match_reads_bytes_present_before_the_call`.
- Safe decoding (Block format, "Implementation notes", Large lengths and Safe decoding): lengths are summed with `checked_add`; an overflow, or output that would pass the limit, is `OutputLimitExceeded`, checked before any byte is copied. Running out of input inside a length, literals or offset is `TruncatedInput`, and so is an empty block. Held by `output_limit_is_enforced_before_copying`, `truncation_in_length_literals_and_offset_is_rejected`.
- End of block rule 1 (Block format, "End of block conditions", 1): a block that ends right after a match is `EndOfBlockViolation`. Held by `rule_1_block_ending_after_a_match`.
- End of block rule 2 (Block format, "End of block conditions", 2): a block with a match whose final literal run is under 5 bytes is `EndOfBlockViolation`; a literals-only block may be any length, including the single zero token for empty input. Held by `rule_2_fewer_than_five_final_literals`, `single_zero_token_is_the_empty_block`.
- End of block rule 3 (Block format, "End of block conditions", 3): the check (fewer than 12 bytes of the block's output from the last match's start to the end) exists but is switched off by default; see the P1-07 entry below. Held by `rule_3_last_match_within_twelve_bytes_of_the_end`.
- The three rules sit behind one private policy constant so a rule is relaxed in a single place. The document permits rejection ("a conformant decoder is allowed to reject the block as incorrect"), not requires it.
- Policy decision (P1-07, from `docs/spikes/P1-06.md`, Policy): rule 1 enforced, rule 2 enforced, rule 3 not enforced (the oracle accepts rule 3 shapes given room in the output buffer; Block format, "End of block conditions": a decoder "is allowed to reject"), empty input rejected as `TruncatedInput`, the single byte 0x00 accepted as the empty block, and the final token's low four bits ignored. Held by `crates/oracle/tests/eob.rs` `end_of_block_probes_agree_with_the_oracle`, `every_prefix_of_small_oracle_blocks_agrees`, `single_byte_corruptions_of_small_oracle_blocks_agree`.
- The low four bits of the final token are ignored: the document sets no requirement on them (Block format, "End of block conditions", 1).
- The oracle's end-of-block behaviour was observed as a black box in `docs/spikes/P1-06.md` (cleanlz4's own measurement through `crates/oracle`): it rejects rule 1 and rule 2 violations and the empty input, accepts the single zero byte and any final-token low nibble, and rejects rule 3 shapes only at exact output capacity. Differential tests therefore decode the oracle side with slack capacity. Held by `crates/oracle/tests/craft.rs` (the builder) and the spike's table.
- Dictionary-prefixed blocks (Block format, "Compressed block format", the offset; Frame format, "Dictionary ID", "a kind of known prefix"): the dictionary is treated as history that sits just before the output, so an offset past the start of the output continues into the dictionary's tail, and a match may start there and run into the output. An offset beyond output plus dictionary is `OffsetOutOfRange`. No trimming is needed because an offset is at most 65,535. Held by `block.rs` tests `match_reaches_into_the_dictionary_tail`, `match_starts_in_the_dictionary_and_continues_into_output`, `offset_past_the_dictionary_start_is_rejected`, `empty_dictionary_behaves_like_no_dictionary`, `only_the_reachable_tail_of_a_long_dictionary_matters`.
- Synthetic inputs (SPEC section 6.3) are generated by `crates/oracle/src/synth.rs`, every byte a function of `fuzz.seed` through `Prng`; block round trips use `conformance.hc_levels` and `conformance.random_block_cases`. Observed black-box fact: the oracle's compression at level 12 faulted when given an empty input through a dangling pointer, so the FFI wrapper passes a pointer to real memory for empty inputs. Held by `crates/oracle/tests/block.rs` and `synth.rs` `inputs_are_deterministic_and_named_uniquely`.
- The conformance corpus (SPEC section 6.3) is generated, not committed: `testdata/conformance/` is gitignored and `testdata/MANIFEST.json` `conformance` records every entry (id, suite, category, kind, tool, input and file hashes and sizes, params) sorted by id with no timestamp; `corpus_sha256` hashes each id and file hash in order. Generation is deterministic from `fuzz.seed`. The block suite compresses each input with the default mode and each `conformance.hc_levels` level; inputs above `conformance.large_input_bytes` get the default and the first level only (cleanlz4's own bound on generation time). Held by `crates/oracle/tests/corpus.rs`.
- Result files (SPEC section 5.4): one `serde` struct per kind with `deny_unknown_fields` in `crates/oracle/src/results.rs`, written pretty-printed with a trailing newline by the binary that ran the work; `by_category` holds only the categories that ran. A conformance entry passes when cleanlz4's decoded output hashes to the recorded `input_sha256`; a decoder panic is caught and counts as a failure. Held by `crates/oracle/tests/results.rs`.
- Frame header check order (Frame format, "Frame Descriptor"): fewer than 4 bytes is `TruncatedInput`; a wrong magic number is `BadMagic`; a missing FLG is `TruncatedInput`; a version other than `01` is `UnsupportedVersion` (Frame format, "Version Number"); missing header bytes for the length the FLG implies is `TruncatedInput`; then reserved bits, the Block MaxSize and the checksum. Held by `frame.rs` tests `rejects_a_bad_magic`, `rejects_versions_other_than_01`, `every_truncation_of_a_full_header_is_truncated_input`.
- Magic Number (Frame format, "Magic Number"): 0x184D2204 little-endian. Held by `rejects_a_bad_magic`.
- FLG byte fields (Frame format, "FLG byte", "Block Independence flag", "Block checksum flag", "Content Size flag", "Content checksum flag", "Dictionary ID flag"): bits 5, 4, 3, 2 and 0 become the descriptor's booleans and optional fields. Held by `parses_content_size_and_dictionary_id` and `crates/oracle/tests/descriptor.rs` `descriptor_matches_oracle_prefs_for_every_combination`.
- Reserved bits (Frame format, "Reserved bits": "Value of reserved bits must be 0"): FLG bit 1 and BD bits 7 and 3 to 0 set is `ReservedBitSet`. Held by `rejects_the_reserved_flg_bit`, `rejects_reserved_bd_bits`.
- Block Maximum Size (Frame format, "Block Maximum Size"): codes 4 to 7 are 64 KB, 256 KB, 1 MB and 4 MB; 0 to 3 are `InvalidBlockMaxSize`. Held by `rejects_block_max_size_values_0_to_3`.
- Content Size and Dictionary ID (Frame format, "Content Size", "Dictionary ID"): eight and four bytes little-endian after the flags, in that order. Held by `parses_content_size_and_dictionary_id`.
- Header Checksum (Frame format, "Header Checksum"): the second byte of XXH32 with seed 0 over the descriptor bytes, always verified even when checksum verification is off, because it guards the layout the decoder is about to trust. Held by `rejects_a_bad_header_checksum`.
- Data blocks (Frame format, "Data Blocks", "Block Size"): the highest bit of the size word marks an uncompressed block, the rest is the data size; `0x00000000` is the EndMark and `0x80000000` is a valid empty uncompressed block. A size field above the frame's Block Maximum Size, and a compressed block that decodes to more than it, are `BlockSizeExceeded` (Frame format, "Data Blocks": "Block_Size shall never be larger than Block_Maximum_Size"). Missing bytes are `TruncatedInput`. Held by `crates/cleanlz4/tests/frame.rs` `zero_size_uncompressed_block_is_valid`, `block_size_field_over_the_maximum_is_rejected`, `decoded_block_over_the_maximum_is_rejected`, `every_truncation_of_a_small_frame_is_truncated_input`.
- Buffers grow only with bytes actually decoded; no header field drives an allocation (Block format, "Safe decoding"). A compressed block decodes into a scratch buffer capped at the frame's Block Maximum Size.
- The frame primitives (`parse_block_header`, `FrameState::decode_data_block`, `FrameState::finish`) work on whole units so the streaming driver can reuse them; the one-shot driver in `frame.rs` walks a complete slice. Held by `crates/oracle/tests/frame.rs` `independent_frames_roundtrip_every_block_size`.
- Linked blocks (Frame format, "Block Independence flag": "up to LZ4 window size, which is 64 KB"): when the flag is 0 the frame keeps the last 65,536 bytes of its decoded output, compressed and uncompressed blocks alike, and decodes each compressed block with them as a prefix; when it is 1 no history is kept and an offset before the block is `OffsetOutOfRange`. Memory is bounded by the window plus one block. Held by `crates/cleanlz4/tests/frame.rs` `linked_block_copies_from_the_previous_block`, `linked_block_copies_from_a_previous_uncompressed_block`, `independent_frame_rejects_an_offset_into_the_previous_block`, `history_reaches_back_65535_bytes_across_blocks`, and `crates/oracle/tests/frame.rs` `linked_frames_roundtrip_every_block_size`.
- Block checksum (Frame format, "Block checksum flag", "Block checksum"): XXH32 with seed 0 over the raw block as stored, four bytes little-endian after the data (an empty block still has one), compared before the block is decoded; a mismatch is `BlockChecksumMismatch`. Held by `crates/cleanlz4/tests/frame.rs` `block_checksum_mismatch_is_rejected`, `empty_block_still_carries_a_block_checksum` and `crates/oracle/tests/frame.rs` `a_flipped_payload_byte_is_caught_by_the_block_checksum`.
- Content checksum (Frame format, "Content checksum flag", "Content Checksum"): XXH32 with seed 0 over all decoded bytes of the frame, fed through the streaming hasher as blocks are produced, stored little-endian after the EndMark; a mismatch is `ContentChecksumMismatch`. Held by `content_checksum_mismatch_is_rejected`, `checksummed_frames_roundtrip`.
- Verification off (Frame format, "Introduction": a decompressor "may also ignore checksums"; SPEC section 6.1, Options): `verify_checksums = false` skips both comparisons and the hashing but still consumes the checksum bytes, and the result reports `checksums_verified: false`. The header checksum is always verified. Held by `verification_off_accepts_bad_checksums_and_reports_it`, `verification_off_still_rejects_a_bad_header_checksum`.
- Content size is validated (Frame format, "Content Size": "It can be skipped by a decoder, or used to validate content correctness"; SPEC section 6.2 lists `ContentSizeMismatch`): the document permits either, so cleanlz4 validates. Decoded bytes passing the declared size are `ContentSizeMismatch` as soon as the count passes it; fewer at the EndMark is the same error. The declared size never drives an allocation. Held by `crates/cleanlz4/tests/frame.rs` `matching_content_size_is_accepted`, `content_size_smaller_than_the_data_is_rejected`, `content_size_larger_than_the_data_is_rejected`, `content_size_zero_with_an_empty_frame_is_accepted` and `crates/oracle/tests/frame.rs` `content_size_frames_roundtrip`.
- Frame boundary rule (Frame format, "Frame Concatenation": decoding concatenated frames "is left outside of this specification"; "Skippable Frames"): at a boundary with no bytes left the flow is finished and empty input decodes to empty output; a regular magic (0x184D2204) starts a frame; a magic 0x184D2A50 to 0x184D2A5F starts a skippable frame whose 4-byte little-endian size says how many bytes to skip; one to three bytes that begin the little-endian form of a known magic (regular, any skippable, legacy 0x184C2102) are `TruncatedInput`; any other bytes are `BadMagic` when no frame has been decoded or skipped yet and otherwise follow the trailing-data policy (`TrailingData` error, or stop with `consumed` at the boundary). Held by `crates/cleanlz4/tests/frame.rs` `empty_input_is_ok_and_empty`, `two_concatenated_frames_decode_in_order`, `all_sixteen_skippable_magics_are_skipped`, `skippable_frame_between_two_frames`, `truncated_skippable_frame_is_truncated_input`, `garbage_at_the_start_is_bad_magic`, `garbage_after_a_frame_is_trailing_data`, `return_remainder_reports_where_it_stopped`, `a_partial_magic_at_the_end_is_truncated_input`, `a_short_non_magic_tail_follows_the_trailing_policy`, and `crates/oracle/tests/frame.rs` `concatenated_oracle_frames_decode`.
- Legacy frame (Frame format, "Legacy frame", "Magic Number", "Block Compressed Size", "EndMark"): magic 0x184C2102, then 4-byte little-endian compressed sizes each followed by that many bytes, with no checksum. The frame ends at the end of input, at a known magic number (regular, any skippable, legacy; left unconsumed), or at a zero block size, which is consumed (the documented Linux kernel Extension). One to three bytes where a size should be is `TruncatedInput`. A size above 8 MiB plus the block format's worst-case growth (8 MiB / 255 + 16) is `BlockSizeExceeded`, and so is a block decoding to more than 8 MiB. "All blocks must be completely filled, except the last one" is an encoder rule and is not enforced. `FrameOutput.kinds` records `Legacy`; a dictionary is never applied. Held by `crates/cleanlz4/tests/frame.rs` `legacy_frame_with_one_block`, `legacy_frame_ends_at_end_of_input`, `legacy_frame_ends_at_the_next_magic_number`, `legacy_frame_ends_at_a_zero_block_size`, `legacy_block_size_out_of_range_is_rejected`, `legacy_truncated_block_is_truncated_input`.
- Legacy blocks are decoded as independent (Frame format, "Legacy frame" is silent on history; Block format, "Compressed block format"). Observed as a black box: the `lz4 -l` program's output of 20 MiB (three blocks) decodes correctly with independent blocks, so no history is carried (`crates/oracle/tests/legacy.rs` `cli_legacy_frame_decodes`). The observation that would change this is an `OffsetOutOfRange` in a block after the first; none occurred.
- One magic classifier (Frame format, "General Structure of LZ4 Frame format" (Magic Number); "Skippable Frames" (Magic Number); "Legacy frame" (Magic Number, EndMark)): `frame::magic_kind` is the only function that knows the three kinds of magic number; the legacy-frame loop ends a frame at a word for which it returns `Some`, so a frame boundary and a frame start can never disagree. `is_magic_prefix` (one to three bytes) is a separate test. Held by `magic_kind_names_the_three_kinds_and_nothing_else` (`frame.rs`) and `legacy_frame_ends_before_a_second_legacy_frame` (`tests/frame.rs`).
- Frame suites (SPEC section 6.3): a combination is block size id 4 to 7, linked or independent, block checksum, content checksum, content size; the 64 are enumerated so that combination `i` (with `hi = i / 4`, `lo = i % 4`) takes its four flags from the bits of `hi` and its block size id from `4 + (hi + lo) % 4`, and uses level `conformance.frame_levels[i % len]`; with four levels each level therefore meets all 16 flag settings and every block size (R1-06; the earlier order varied the block size fastest, which tied each level to one block size). Held by `crates/oracle/tests/corpus.rs` `every_frame_level_meets_every_block_size`. The `synthetic` suite takes every synthetic input with all 64; `frames-cantrbry` every Canterbury file with all 64; `frames-silesia` every Silesia file with `conformance.silesia_combos_per_file` combinations drawn with `Prng` seeded by `fuzz.seed` xor an FNV-1a hash of the file name. Inputs over 1 MiB reach the frame compressor in 1 MiB chunks with auto-flush on. Entries are `kind` `frame`, `tool` `lz4f`.
- Category rule for corpus frame entries: `content-size` when the content size is present, else `checksums` when either checksum is on, else `frame-linked` or `frame-independent`; the synthetic suite's entries are `synthetic`. Held by `crates/oracle/tests/corpus.rs` `categories_follow_the_precedence_rule`, `frame_suites_cover_all_64_flag_combinations`, `every_frame_level_and_block_size_appears`, `the_oracle_decodes_every_generated_synthetic_frame`.
- Streaming decoder (SPEC section 6.1, Streaming; Frame format, Introduction: "using only an a priori bounded amount of intermediate storage"): `Decoder::decode(input, output, end_of_input)` collects one unit at a time (a frame header of at most 19 bytes, a block size word, one block's data with its checksum, the content checksum) and calls the same `frame.rs` primitives as the one-shot driver on whole units, so the two paths cannot drift. It holds at most one decoded block for delivery; nothing is allocated from a header field. The header is re-parsed after each byte, so an error decided by the bytes present (bad magic, version, reserved bits, block size, header checksum) is reported at the same point as in the one-shot path. Status per call, first that applies: `OutputFull` (decoded bytes wait and the output is full), `FrameDone` (a frame ended and its bytes are delivered; the call returns there, once per frame), `Done` (`end_of_input`, all input consumed, at a boundary), else `NeedsInput`. `end_of_input` inside a unit is `TruncatedInput`; after `Done` every call returns `Done`; after an error every call returns that error and the failing call's output is not reported. Held by `crates/cleanlz4/tests/stream.rs`.
- Streaming frame boundary (SPEC sections 2 and 6.1; Frame format, "Frame Concatenation", "Skippable Frames", "Legacy frame"): with no bytes left and `end_of_input` the decoder is `Done`; a regular, skippable (0x184D2A50 to 0x184D2A5F) or legacy (0x184C2102) magic starts that frame; one to three bytes that begin a known magic wait for more, or are `TruncatedInput` at `end_of_input`; any other byte is left unconsumed and is `BadMagic` for the first frame and `TrailingData` (or `Done` under `ReturnRemainder`) after. A skippable frame is skipped by counting its declared size down, never buffered. A legacy frame ends at end of input, at a known magic or at a zero block size, and is `NeedsInput` at a block boundary with nothing buffered while input may follow; its blocks are decoded under the output limit as in the one-shot path (`min(8 MiB, remaining allowance)`). `FrameDone` is reported for skippable and legacy frames too. Held by `skippable_frame_first_streams_like_one_shot`, `skippable_user_data_is_skipped_without_buffering`, `legacy_frame_ends_at_end_of_input`, `legacy_frame_then_regular_frame`, `concatenated_frames_report_frame_done_each`, `return_remainder_stops_before_the_trailing_bytes`, `trailing_garbage_is_trailing_data` and `every_one_shot_test_frame_matches_when_streamed_bytewise`.
- Output limit (SPEC sections 2, 5.1, 6.2; Block format, "Implementation notes", Safe decoding): `DecodeOptions::max_output_bytes` (default `DEFAULT_MAX_OUTPUT_BYTES`, the `limits.max_output_bytes` key) counts decoded bytes across the whole call or decoder, all concatenated frames together; in the streaming decoder bytes decoded but not yet delivered count, because they are counted when decoded. Each block is decoded with `max_len` = min(Block Maximum Size, remaining allowance), so the error is raised before the bytes are written: `OutputLimitExceeded` when the allowance was the smaller bound, `BlockSizeExceeded` otherwise. A frame header whose content size exceeds the remaining allowance is `OutputLimitExceeded` at the header, before any block is read (so a huge declared size no longer reaches `ContentSizeMismatch`). The one-shot output grows only as blocks arrive and is never reserved from a header field. Memory bound, measured (R1-02): the limit plus one block plus 65,536 bytes of history (plus the input and any dictionary), at any limit. Three buffers are held to it: the output's capacity grows geometrically but never past the bytes already in it plus the remaining allowance; the frame's scratch buffer never grows past the block bound; the history is trimmed to the window before a block is added, so its capacity stays near 65,536 bytes. Allocation failure is reported as `OutputLimitExceeded` (no allocation error exists in `Error`). Accounting: a reallocation counts only its size change. Held by `crates/cleanlz4/tests/limits.rs` `one_shot_output_capacity_never_exceeds_the_limit`, `legacy_output_capacity_never_exceeds_the_limit` and `crates/oracle/tests/limits.rs` `a_small_frame_expanding_past_the_limit_fails`, `bomb_peak_allocation_is_bounded`, `bomb_peak_allocation_is_bounded_past_several_blocks` (a counting allocator in that test binary only).
- Benchmarks (SPEC section 1: "Performance is measured and reported. It is not a gate."; section 8, Phase 4): every corpus file in the manifest is compressed once by the oracle (4 MiB blocks, independent, content checksum on, level 0) and decoded `bench.repeats` times by each side; the best time of each side is kept and reported as MB/s of decoded bytes (10^6 bytes), rounded to one decimal. The oracle side goes through `oracle::frame::decompress_frames`, which allocates a 64 KiB scratch buffer per frame and appends to a `Vec`, so the oracle figures of small files include that overhead. No target is set and the decoder was not optimized. Held by `crates/oracle/tests/bench.rs`.
- Evidence index (SPEC sections 1, 5.4 and 8, Phase 5): `docs/EVIDENCE.md` lists every tracked result file, the manifest, `docs/DESIGN.md` and every spike in one sorted fenced block, quotes each result file's headline counts, and states SPEC section 1's Done items as met, not met or owed to the summarize stage, naming blocked and skipped tasks. A listed file must exist and every tracked result file must be listed. Held by `crates/oracle/tests/results.rs` `evidence_index_lists_every_result_file`.
- Dictionary oracle (SPEC section 9 Q2, owner decision; Frame format, "Block Independence flag", "Data Blocks"): the binding lacks the dictionary decoder, so the `lz4` program run as a black box (`lz4 -d -D <dict> -c`) decodes a block wrapped in a minimal hand-built frame (independent blocks, no checksums, header checksum from cleanlz4's XXH32). Dictionary-dependent blocks come from compressing `[dict, data]` as linked blocks and keeping the second block (`oracle::dict::dict_block`). Held by `tests/dict.rs`.
- Preset dictionary and Dict-ID (Frame format, "Dictionary ID flag", "Dictionary ID", "Block Independence flag"; SPEC sections 6.1 Options and 6.2): a frame with a Dict-ID and no dictionary is `DictionaryRequired`; a frame Dict-ID and a dictionary id that are both present and differ are `DictionaryMismatch`; otherwise a supplied dictionary is used, also for a frame without a Dict-ID. Independent blocks all take the dictionary's last 65,536 bytes as prefix; linked frames start their history from it ("used once, at the beginning of the frame"). Each regular frame restarts from the dictionary; the streaming decoder applies the same rules through `FrameState::new`. Held by `tests/frame.rs` (six dict tests). Oracle side: `oracle::dict::dict_frame` assembles frames by hand from `dict_block` output; the C library's frame API cannot decode them; the `lz4` program does, and `tests/dict_corpus.rs` compares it with cleanlz4. Held by `tests/dict_frame.rs` and `tests/dict_corpus.rs`.
- Special conformance suites (SPEC sections 6.3, 6.5 last paragraph, 9 Q2 and Q3; Frame format, "Dictionary ID", "Skippable Frames", "Legacy frame", "Frame Concatenation"): four suites that the oracle's frame API cannot produce are assembled by hand or with the `lz4` program as a black box. `dictionary`: for each `dict.sizes_bytes` size and each Canterbury file of at least twice that size, the dictionary is the file's first bytes (written to `dictionary/<file>/dict-<size>.bin`, recorded with `dict_sha256`, `dict_source`, `dict_offset`, `dict_dependent`) and the data the next 256 KiB; four entries per pair (raw block, linked frame with Dict-ID, independent frame with Dict-ID, linked frame without), tool `hand`, decoded by cleanlz4 with the dictionary (id passed only when the frame has one); the C library's frame API cannot decode them; the `lz4` program does, and `tests/dict_corpus.rs` compares it with cleanlz4. `skippable`: all 16 magic values alone, a zero-length one, and skippable frames before, between and after oracle frames. `legacy`: `lz4 -l` over each Canterbury file and 20 MiB of word salad (each records `cli_version`), plus a two-block and a zero-terminated frame by hand. `concatenated`: two to four oracle frames with different preferences, legacy then regular, regular-skippable-regular. The oracle rejects legacy frames, so legacy-bearing entries are excluded from its acceptance check. Held by `tests/corpus.rs` (`the_four_special_suites_each_have_entries` and three more).
- Malformed corpus (SPEC sections 6.4, 6.2, 5.4; Frame format and Block format rules named per file in `testdata/malformed/index.json`): `oracle::malformed::cases` builds every file by hand with `craft` and `craft_frame`, one broken rule per file and otherwise valid (reserved-bit files carry a correct header checksum for their bytes). Expected variants come from the rules, not from running the decoder: header faults, every truncation offset of a small frame and of one with both checksums and a content size, offsets (zero, before the output, into an earlier independent block, beyond linked history), the end-of-block rules that `docs/spikes/P1-06.md` says are enforced (rules 1 and 2 and the empty block; rule 3 is not enforced so it has no file), checksum and content-size faults, block sizes over the maximum, Dict-ID without a dictionary, trailing garbage, and raw-block versions of offset and truncation. Frames run with default options, blocks with `diff.max_output_bytes` recorded as `max_output`. Held by `tests/malformed.rs`. The corpus also holds the Dict-ID-without-dictionary case (`DictionaryRequired`), since dictionaries exist; R3-02 re-ran it and wrote `testdata/results/malformed-R3-02.json` (144 of 144, 0 panics).
- Streaming frames of every kind (SPEC section 6.1, Streaming; Frame format, "Frame Concatenation", "Skippable Frames", "Legacy frame", "Dictionary ID"): the streaming decoder follows the one-shot frame boundary rule. A skippable frame is skipped by counting its declared size down as input arrives, never buffered, and ends with `FrameDone`; a legacy frame collects each 4-byte word and block, ends at end of input, at a zero word (consumed) or at a known magic (its four bytes carry over to the next boundary), and reports `NeedsInput` at a block boundary with nothing buffered while input may still come; dictionary and Dict-ID rules are `FrameState::new`'s, shared with the one-shot path. `FrameDone` is reported for every kind. Under `ReturnRemainder` the streaming decoder stops at the first byte that cannot continue a magic number and leaves it unconsumed; the one to three bytes of a partial magic taken before it are handed back by `Decoder::remainder`, so the caller's remainder is `remainder()` followed by the input not consumed, exactly the bytes the one-shot driver leaves after its `consumed` count (R1-05; the alternative of not reporting prefix bytes as consumed until the magic is confirmed was rejected because a caller feeding one byte at a time from a fixed-size window would never advance). Held by `return_remainder_leaves_a_trailing_magic_prefix_unconsumed`. Held by `tests/stream.rs` (nine new tests, including `every_one_shot_test_frame_matches_when_streamed_bytewise`).
- Chunking invariance (SPEC section 8, Phase 3; section 2; Frame format, Introduction on a bounded amount of intermediate storage): `crates/oracle/tests/chunking.rs` draws `stream.chunking_cases` cases from `fuzz.seed` (each case's seed is printed on failure), each with random frame preferences and mixed-compressibility inputs, every tenth case a concatenation, a leading skippable frame or a hand-built legacy frame, and input and output chunk regimes of 1, 2, 3, 7, 64, 4096 or up to 70,000 bytes (one-byte regimes only for inputs up to 4 KiB). Streamed bytes must equal the one-shot decoder's and the original input, consuming all input and ending in `Done`; a tenth as many truncated or corrupted frames must give the same `Error` or bytes both ways. Held by `chunking_invariance_random_chunks`, `chunking_invariance_on_errors`, `regimes_include_one_byte_input_and_one_byte_output`.
- No-panic fuzz targets (SPEC section 8 Phase 4 (a); section 1 property 3; Block format, "Safe decoding"; Frame format, "Frame Concatenation"): each `fuzz/fuzz_targets/no_panic_*.rs` is one line over `oracle::fuzz_logic`, so the logic runs on stable Rust. `no_panic_block`: bytes 0 and 1 are `max_output` (little-endian value times 16), byte 2 splits the rest into dictionary and block in proportion (`len * byte / 256`). `no_panic_frame`: first byte bits are trailing policy, verification off, dictionary supplied (next 64 bytes) and dictionary id (little-endian value of its first four bytes); the output cap is `fuzz.max_output_bytes`. `no_panic_stream`: bytes 0 and 1 pick the chunk regimes and the streamed outcome must equal the one-shot outcome; the output buffer grows with the one-shot output so that a bomb needs at most about a million calls. None calls the oracle. Held by `tests/fuzz_logic.rs`.
- Differential fuzz targets (SPEC section 8 Phase 4 (b) and (c); section 6.4; section 5.1 `fuzz.seed`): `diff_roundtrip` derives preferences, target length (up to 300 KiB) and chunking from its first four bytes (byte 0: block size id, linked, block checksum, content checksum, content size; byte 1: frame level index and chunk count; bytes 2 and 3: length), expands the rest with perturbations from `Prng` seeded by `fuzz.seed` and a hash of the bytes, compresses with the oracle and requires cleanlz4 and the oracle to return the input; inputs whose hash is a multiple of eight also take the block form (`compress_default` or an HC level from `conformance.hc_levels`). `diff_accept` runs `diff::compare_frame` and `diff::compare_block` (cap: 256 times the input plus slack, at most `fuzz.max_output_bytes`); a `Diverge` is written to `$CLEANLZ4_DIVERGENCE_DIR/<16 hex of SHA-256>.bin` unless `fuzz.max_divergence_files` files are already there, and panics when the variable is unset. `Skipped` is not a divergence. Held by `tests/fuzz_logic.rs`.
- Fuzz runner (SPEC sections 7, 5.4, 5.1, 3.5, 3.6): `fuzz_run --target <t> --task <id> [--smoke]` seeds `fuzz/corpus/<t>/` from the malformed corpus, runs `cargo +nightly fuzz run -a <t> fuzz/corpus/<t> -- -max_total_time=<fuzz.seconds_per_target, or fuzz.smoke_seconds> -seed=<fuzz.seed> -print_final_stats=1` with `CLEANLZ4_DIVERGENCE_DIR` set, logs every line with the elapsed seconds to `fuzz/logs/<t>-<id>.log`, and writes the result from what it observed: `runs` from the final statistics, `crashes` as new files under `fuzz/artifacts/<t>/`, `divergences` as new `.bin` files in the divergence directory, `corpus_entries` as the files in the corpus. A result is data, so crashes still exit zero; each crash is copied to `testdata/regressions/<t>-<16 hex of SHA-256>.bin`, and an entry is added to `testdata/regressions/index.json` only when the input is triaged. It exits non-zero when the fuzzer cannot start or stops early without a crash. A smoke run writes its result and divergences to a temporary directory. Held by `tests/fuzzrun.rs` and `tests/regressions.rs`.
- Dictionary entries against the `lz4` program (SPEC section 6.5, Dictionary oracle; Frame format, "Dictionary ID"): every `dictionary` entry of the conformance corpus, frames through `oracle::cli::decompress_frame_with_dict` and bare blocks through `oracle::cli::decompress_block_with_dict` (a minimal hand-built frame), is decoded by the `lz4` program and by cleanlz4 with the entry's dictionary and id; both outputs must equal the recorded input in length and SHA-256 and each other. A frame with a Dict-ID decoded without a dictionary must be `DictionaryRequired`. Held by `tests/dict_corpus.rs` (`every_dictionary_entry_decodes_identically_with_the_lz4_program_and_cleanlz4`, `dict_id_frames_without_a_dictionary_are_dictionary_required`, `the_dictionary_category_covers_blocks_frames_and_every_configured_size`).
- One scratch buffer per frame (SPEC section 6.1, Bounded memory; Frame format, "Block Maximum Size" ("This information is useful to help the decoder allocate memory"); Block format, "Implementation notes", Safe decoding): a regular frame's `FrameState` owns one `scratch` `Vec` that every compressed block decodes into (taken, cleared, decoded into with the same bound as before, put back); a legacy frame owns one for its whole frame (`decode_legacy_frame` locally, the streaming `Decoder` in a field replaced when the frame ends). At most one scratch buffer is alive, none outlives its frame and its capacity never passes one block's bound, so the section 6.1 bound is unchanged. Held by `streaming_legacy_scratch_is_freed_at_the_end_mark`, `streaming_legacy_scratch_is_freed_at_the_next_magic`, `one_shot_fresh_allocations_do_not_grow_with_the_block_count`, `streaming_fresh_allocations_do_not_grow_with_the_block_count` and `legacy_fresh_allocations_do_not_grow_with_the_block_count` (`tests/scratch.rs`) and the four memory tests `bomb_peak_allocation_is_bounded`, `bomb_peak_allocation_is_bounded_past_several_blocks`, `one_shot_output_capacity_never_exceeds_the_limit`, `legacy_output_capacity_never_exceeds_the_limit`.

## Differential rules

- Zero offset (Block format, "Compressed block format": "0 is an invalid `offset` value ... denotes an invalid (corrupted) block"): the oracle accepted a corrupted block whose offset became 0 (found by `single_byte_corruptions_of_small_oracle_blocks_agree`), while cleanlz4 returns `ZeroOffset`. In block differentials, cleanlz4 `ZeroOffset` against an oracle accept is allowed; every other accept/reject pair must agree. Decoding on the oracle side uses the original length plus 65,536 bytes of capacity (P1-06).

- `legacy-frame` (Frame format, "Legacy frame"; spike `docs/spikes/P2-09.md`): the oracle's frame decoder rejects a legacy frame as an unknown frame type while cleanlz4 decodes it. In frame differentials, a cleanlz4 accept whose `kinds` contains `Legacy` against an oracle reject is `Agree`. Held by `crates/oracle/tests/diff.rs` `an_unlisted_disagreement_is_diverge`, `legacy_normalization_requires_a_legacy_frame` and `every_probe_is_agree_or_a_named_normalization`.
- `zero-offset` (Block format, "Compressed block format", offset): carried over from the block rule above and applied in both block and frame comparisons. Held by `zero_offset_block_is_agree_through_its_named_normalization`, `every_probe_is_agree_or_a_named_normalization` and `tests/eob.rs`.
- Dict-ID retry (Frame format, "Dictionary ID": the dictionary "can also be passed off-band"): the oracle accepts a frame with a Dict-ID and no dictionary, so when cleanlz4 reports `DictionaryRequired` the comparison re-runs it with an empty dictionary with no id and compares that result. Held by `dictionary_required_is_retried_with_an_empty_dictionary`.
- `end-of-block-room` (Block format, "End of block conditions": "a conformant decoder is allowed to reject the block as incorrect"; cleanlz4's own measurement, P4-09): cleanlz4 enforces rules 1 and 2, so a block whose final literal run after a match is under five bytes is `EndOfBlockViolation`. The oracle accepts some such blocks, only when its output buffer has spare room: with a final run of four literals it accepted every match length from 19 up at a capacity of 65,536 bytes of slack and rejected all of them at exact capacity, and with three literals it accepted a match of 300 (probe over match lengths 4 to 300, offsets 1 and 8, final runs of 0 to 4). The acceptance depends on the buffer, not on the block, as for rule 3 in `docs/spikes/P1-06.md`. A cleanlz4 `EndOfBlockViolation` against an oracle accept is `Agree` in block and frame comparisons. Held by `end_of_block_room_is_a_named_normalization` and the 100 inputs under `testdata/regressions/`.
- Output cap: both sides run under `diff.max_output_bytes`; either side over the cap is `Skipped("output-cap")`. Block comparisons give the oracle 65,536 bytes of slack capacity (docs/spikes/P1-06.md). Held by `an_unlisted_disagreement_is_diverge`, `compare_block_agrees_on_the_p1_06_probes`, `compare_block_skips_when_only_the_oracle_goes_over_the_cap`.
- Every other disagreement, including different outputs when both accept, is `Diverge`. Held by `unequal_outputs_are_reported_as_diverge`.
